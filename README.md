# Where Does Recursive Feedback Fail?
### Contextual Symbol Generation and Attention-Head Dependence

**University of the Witwatersrand · Natural Language Processing · Project 1 (2026)**

This is the source-code and results repository for a controlled study of **model collapse** and **in-context learning (ICL)**. It builds on the two-layer, eight-head transformer and the Omniglot task from [Singh et al. (2024)](https://arxiv.org/abs/2404.07129).

**New reader?** Read [the experiment in plain language](#1-what-the-project-does), follow [installation](#3-installation), then run `python run.py results` to view the original measurements. The required lecturer submission instructions are in [README.txt](README.txt); [the full setup guide](SETUP_GUIDE.md) explains the trained checkpoint prerequisites.

## 1. What the project does

An input prompt contains two different handwritten characters with numerical labels, followed by a query character. Labels are randomly reassigned between episodes, so the transformer must use **this prompt**, not memorized global labels.

For example, given **A → 3; B → 1; query A**, the Base model should answer **3**. Our Extended model also predicts a next character from the context and that character's label, such as **(3, B, 1)** or **(3, A, 3)**. A prediction of C is context-invalid if only A and B were shown, even if the accompanying number looks plausible.

A first model, **G0**, learns from correct training targets. Each successive model, **G1–G10**, trains from scratch using targets generated by its predecessor. **The input character examples remain real Omniglot features**: this is *target-only synthetic feedback*, not fully generated input sequences. We compare this recursive condition with clean targets, frozen-G0 targets and a 50/50 real–synthetic target mixture.

We measure (i) numerical-label retrieval, (ii) whether a sampled next character was in the prompt, and (iii) how attention-mediated responses change when we modify the prompt. We then repair invalid synthetic character–number targets to test whether performance can recover. Model outputs and causal attention-head interventions answer different questions and must not be conflated.

## 2. Main finding and scientific boundaries

At G10, the five-seed mean **clean-minus-recursive performance difference** is **+9.22 percentage points** for Base contextual-label accuracy and **+19.73 percentage points** for Extended sampled next-character validity. In five matched repair runs, correcting invalid generated next-character/number targets increases valid-symbol probability mass by **21.17 percentage points** and the context-switch preference by **5.94 logit units**.

These are **original validation measurements**, not results regenerated by this README. The original 100-class final test was opened earlier at G3; the G10 analyses are validation-only. Base and Extended training budgets differ, so their numerical effect sizes cannot establish a controlled comparison of vulnerability. Repair updates all model weights, and activation patching alone does not identify one unique causal induction head.

See the results dashboard under `docs/experiments/g10_five_seed/`, `docs/experiments/q2_activation_patching/`, and `docs/experiments/q2_repair_mediation/`. Historical and auxiliary experiments are retained in [the archive branch](https://github.com/huziibee/nlp_ass_one/tree/research-archive-20261022); see [PROVENANCE_AND_BRANCHES.md](PROVENANCE_AND_BRANCHES.md).

## 3. Installation

The most reliable environment is **Ubuntu (including WSL2) with Python 3.10**, because the upstream JAX and Equinox APIs are pinned. Git and Internet access are needed for the original features and model checkpoint downloads.

```bash
git clone --recurse-submodules https://github.com/huziibee/nlp_ass_one.git
cd nlp_ass_one
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run.py check
python run.py data-check
python run.py tests
python run.py results
```

On Windows, use WSL2/Ubuntu where possible. Native PowerShell venv activation and platform notes are in [SETUP_GUIDE.md](SETUP_GUIDE.md). If you cloned without the upstream repository, run `git submodule update --init --recursive`.

`requirements.txt` is the required dependency file; it includes the pinned model runtime through `requirements-model-smoke.txt` and optional Jupyter tooling. Do **not** silently upgrade JAX and treat results as an unchanged reproduction.

## 5. Reproducing training and graphs

Trained checkpoints are too large to ship as ordinary source files. To run the smoke tests or reproduce training, first download the **matching original artifacts** from the GitHub Actions runs/releases into the exact directory structure described in [SETUP_GUIDE.md](SETUP_GUIDE.md). Check the `model.eqx` or `extended_g0_model.eqx` plus `metrics.json` or original Base configuration before proceeding.

On a prepared system, the principal source scripts are:

```bash
python scripts/paper_base_full.py
python scripts/extended_g0.py --artifact-root outputs/base_full_1m --steps 9375 --batch-size 32 --eval-every 937 --eval-count 512 --learning-rate 0.0003 --out outputs/extended_g0_full
python scripts/base_recursive.py --artifact-root outputs/base_full_1m --generations 10 --steps 31250 --batch-size 32 --eval-every 3125 --eval-count 512 --arms clean_only recursive_replacement real_anchor_half frozen_g0 --out outputs/new_base
python scripts/extended_recursive.py --base-artifact outputs/base_full_1m --extended-g0-artifact outputs/extended_g0_full --generations 10 --steps 9375 --batch-size 32 --eval-every 937 --eval-count 512 --learning-rate 0.0003 --arms clean_only recursive_replacement real_anchor_half frozen_g0 --out outputs/new_extended
```

**Warning:** These are computationally expensive, fresh training runs that will **not** reproduce five-seed historical checkpoints just by executing once. The five-seed studies use separate recorded seeds and checkpoint chains. See `docs/experiments/` and the original `.github/workflows/` for their parameters and upstream run IDs. **Do not rerun `scripts/evaluate_sealed.py`**: the course final-test boundary was already crossed historically.

For original G1–G10 plotting without retraining, inspect the tracked SVGs in `docs/experiments/archived_original_runs/g10_dashboard/`, or run `scripts/render_g10_dashboard.py --input ... --out ...` on a complete set of original generation trajectory files. See the setup guide for input layout.

## 6. Verified methodological sensitivity controls

The assignment brief (sections 1.3–1.4) requires the Base and Extended sequence-generation tasks and permits additional adjustments; it **does not require synthesizing entire input prompts**. Our primary study recursively generates label/continuation targets while preserving the real Omniglot feature prefixes. The project also contains two completed exploratory controls with their own original evidence:

- **300k exposure parity:** a Base model trained from G0 through G10 at 300,000 examples per generation, matching Extended's sample budget but **not its architecture or task**. Results: `docs/experiments/base_full_budget_300k/summary.json` (one model seed).
- **Accumulating synthetic-example history:** retains a real anchor and past synthetic targets while the training pool grows, with a matched clean-history control. Results: `docs/experiments/cumulative_corpus/summary.json` (one model seed).

Run `python run.py methodology` to validate generation completeness, control comparability and split/test isolation, then create `outputs/reports/METHOD_CONTROLS.md`, CSV and JSON. `python run.py results` includes these displays. Do **not** combine single-seed sensitivity estimates with the five-seed main comparison or claim full input-context recursion.

Checkpoint preparation is now available via `python run.py restore-checkpoints` (requires an authenticated `gh` CLI) and `python run.py verify-checkpoints`. Restores refuse to overwrite pre-existing checkpoint directories; verification records local SHA-256 digests and checks the original metadata. The hashes identify downloaded bytes; they are not an independent published checksum comparison. Full historical G0–G10 recomputation is computationally expensive and **has not been rerun end-to-end from a fresh initialization in this audit**.

## 8. Fresh five-seed G0–G10 replication (optional full-cost study)

The complete **new-initialization** replication is defined in [`.github/workflows/fresh-five-seed-full.yml`](.github/workflows/fresh-five-seed-full.yml), with a machine-checkable protocol in `scripts/fresh_five_seed.py`. It runs **five entirely new G0 models for Base and five entirely new G0 models for Extended**, then trains clean and recursively generated targets separately over ten full-length generations for each seed.

- Base G0 and each descendant: **1,000,000** training examples. Extended G0 and each descendant: **300,000** examples.
- All initializations and data-order seeds are fixed *before* running and differ from the original five research seeds. Failed/weaker G0 seeds are retained and reported, not filtered.
- No historical checkpoint is loaded as starting model weights. Extended G0 does use the **new Base G0 configuration**, not its trained parameters. The original pretrained ResNet18 Omniglot features are part of the frozen dataset—not something retrained here.
- Each independent training job must emit model weight files and metrics for **all ten generations**. Reassembly fails if a generation, checkpoint, seed, budget, experimental condition, or final-test safeguard is missing.
- The final aggregate runs only if all training jobs succeed and publishes `fresh_five_seed_summary.json` plus seed-level CSV, **separately** from the 2026 historical metrics.

Inspect the deterministic plan without any model training:

```bash
python run.py fresh-plan
```

After the GitHub workflow finishes, the saved artifacts can be restored under `outputs/fresh_five_inputs/` as described in [the full replication guide](FRESH_FIVE_SEED_REPRODUCTION.md), then independently audited:

```bash
python run.py fresh-aggregate
```

**Status is determined by the GitHub Actions run, not the presence of the workflow YAML.** The old five-seed study was executed successfully and reaggregated; that does *not* establish that a new complete training run has finished. The protected original 100-class final test was opened at G3 and must not be reopened. G10 remains validation-only.
