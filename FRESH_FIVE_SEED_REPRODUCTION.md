# Fresh five-seed G0–G10 reproducibility protocol

**Purpose:** Run a genuinely new set of five independently initialized Base and five independently initialized Extended models **from scratch**, then train clean and recursively sampled descendant models at generations G1–G10. This is not a new aggregation of the October 2026 historical five-seed checkpoints.

## Scientific contract

The upstream input dataset remains the **original 1,623-class precomputed Omniglot/ResNet18 feature HDF5** in the pinned `external/icl-dynamics` submodule. We train newly initialized transformer models, **not** a new ResNet18 feature extractor. We use the frozen 50/1,473/100 class split, with no access to the already-opened final-test partition. The recursive condition replaces output targets generated by the preceding model; contextual feature inputs stay genuine. This is the same well-defined mechanism as the original study.

| Requirement | Base | Extended |
| --- | --- | --- |
| New G0 weights per seed | Yes; five new 2-layer, 8-head transformers | Yes; five new three-output transformers |
| G0 examples per seed | 1,000,000 | 300,000 |
| Descendant generations per seed/arm | G1–G10 | G1–G10 |
| Examples per descendant | 1,000,000 | 300,000 |
| Conditions | `clean_only`, `recursive_replacement` | `clean_only`, `recursive_replacement` |
| New initialization seeds | 1005, 1105, 1205, 1305, 1405 | 9054, 10054, 11054, 12054, 13054 |
| Matching data-order seeds | 39001, 40001, 41001, 42001, 43001 | 9054, 10054, 11054, 12054, 13054 |

A fixed seed is repeated across the clean and recursive arms for a particular task and pair, allowing a paired comparison. The five *different* initialization seeds define independent model replicates. The choice of seeds is predeclared, and weak baseline seeds are not removed following validation.

For the Extended model, the matching new Base G0 artifact is accessed only to read its training **configuration** (architectural and data-split metadata); no learned Base weights initialize Extended G0. Each Extended G0 is initialized independently.

The aggregate must contain:

- Exactly **10 newly trained G0 models** (five Base and five Extended).
- Exactly **20 G1–G10 arms** (two tasks × five seeds × two target conditions).
- Exactly **200 newly trained descendant checkpoints** (20 arms × ten generations).
- Exact specified optimizer-example budgets and class splits.
- An original `metrics.json` for every G0 or descendant, with the correct seed and generation, and a recorded `final_test_evaluated: false`.
- All five paired effects for each declared outcome; descriptive confidence intervals across model seeds.
- Saved results under new names, never overwriting the historical G10 evidence.

## Files and command entry points

```text
.github/workflows/fresh-five-seed-full.yml  # Full workflow, matrix, artifacts
scripts/fresh_five_seed.py                 # Frozen plan + rigorous validator
tests/test_fresh_five_seed.py              # Tampering/shape/seed safety tests
```

Print the plan locally (no JAX installation or model weights required):

```bash
python run.py fresh-plan
```

## Starting a fresh training run

1. Open [GitHub Actions](https://github.com/huziibee/nlp_ass_one/actions/workflows/fresh-five-seed-full.yml) and choose **Run workflow** on `main` (after the reviewed workflow is merged).
2. Alternatively, with authenticated GitHub CLI:

```bash
gh auth login
gh workflow run fresh-five-seed-full.yml --ref main
```

3. The workflow checks source, dataset and tests, then trains **all new** Base G0 seeds; only after they complete does it train all Extended G0 seeds. Clean and recursive descendants are each trained at full example counts.
4. The aggregator job is guarded with `needs: [fresh-base-arms, fresh-extended-arms]`. It is **skipped** if a required training job fails or is cancelled. This is deliberate: partial results cannot be labelled as five complete seed pairs.
5. Upon successful completion, download the `fresh-v1-independent-five-seed-results` artifact containing `fresh_five_seed_protocol.json`, `fresh_five_seed_rows.csv` and `fresh_five_seed_summary.json`. Preserve the workflow run URL and commit SHA along with the result files.
6. Download and archive G0 and G1–G10 model/checkpoint artifacts before GitHub's artifact retention expires. Current workflow requests 90 days, but organization/repository policies can override it.

**Cost and time:** Full CPU retraining is computationally expensive and the GitHub Actions account can incur billed usage. Each branch/arm is a separate job. An ordinary unit-test or four-step smoke run does not establish this study's completion. Individual jobs have timeouts; a failed timeout is a failed replicate, not a partial success.

## Independently validating downloaded artifacts

After downloading the original artifacts for a *single full workflow run*, use:

```bash
mkdir -p outputs/fresh_five_inputs
gh run download RUN_ID -n fresh-v1-base-g0-0 -D outputs/fresh_five_inputs/base_g0/fresh-v1-base-g0-0
gh run download RUN_ID -n fresh-v1-extended-g0-0 -D outputs/fresh_five_inputs/extended_g0/fresh-v1-extended-g0-0
gh run download RUN_ID -n fresh-v1-base-arm-0-clean_only -D outputs/fresh_five_inputs/base_arms/fresh-v1-base-arm-0-clean_only
gh run download RUN_ID -n fresh-v1-extended-arm-0-clean_only -D outputs/fresh_five_inputs/extended_arms/fresh-v1-extended-arm-0-clean_only
```

Repeat the same pattern for indices **0–4** and both arms. Be sure every artifact comes from the **same** newly trained workflow run, not a historical run. The output layout is:

```text
outputs/fresh_five_inputs/
  base_g0/fresh-v1-base-g0-0/{independent_protocol.json,safe_train_val_smoke/...}
  extended_g0/fresh-v1-extended-g0-0/{metrics.json,extended_g0_model.eqx}
  base_arms/fresh-v1-base-arm-0-clean_only/{summary.json,clean_only/g01/...}
  extended_arms/fresh-v1-extended-arm-0-clean_only/{summary.json,clean_only/g01/...}
  ...other seeds/arms...
```

Then:

```bash
python run.py fresh-aggregate
```

The verifier refuses to report success unless **all ten G0 and 200 descendant checkpoints** are present, every generation is ordered G1–G10, experimental seeds and budgets match, and the test isolation flags remain false. A failure means **the replication is not fully verified**. The aggregator reads checkpoint-associated metrics; it does not rerun the model forward pass. Its numbers are kept in a separate `outputs/fresh_five_results/` directory.

## What this does *not* repair

- The original 100-class test set was opened during the historical G3 experiment. A fresh random seed does **not** restore that data partition to untouched status. New G10 measurements here use only validation data.
- Training budgets across *task types* remain different because these are the original specified model budgets. A separate 300k Base matched-budget sensitivity control is available in the repository, with only one historical model seed. That control does not make architecture/task complexity comparable.
- The model-collapse process here recursively generates **targets** on original real Omniglot input features; it does not generate every new input symbol or appearance from scratch.
- A passing full training and metrics check demonstrates software execution and one reproducibility protocol. It cannot alone establish uniqueness of a mechanistic causal explanation, independent generalization, publication readiness, or an examiner mark.

## Acceptance criteria for describing the fresh experiment as completed

Do not use the sentence “fresh full five-seed retraining completed” unless **all** of the following evidence is available: the current workflow run is marked **success**; every G0 and descendant job succeeded; the final `verify-all-fresh-results` aggregator job succeeded; and its JSON, CSV, model checkpoint packages and logs were preserved and inspected. The historical five-seed reaggregation passing is not sufficient.
